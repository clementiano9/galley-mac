# UX Feature-Gap Analysis — tiny-viewer
**Analyst**: feat-ux  
**Date**: 2026-06-08  
**Scope**: Discoverability deficits and table-stakes UX absent from native macOS markdown viewer class (Preview / Bear / Typora / iA Writer). Every status claim was verified against source before being written.

> **WAAD-grounded requirements:** U-02, U-04, U-06, U-13, U-16 (and F-05/F-18, F-19, F-22 from `spec-gaps.md`) have crystal-clear, build-ready requirement definitions — traced through the URD/WAAD and critic-verified — in [`waad-grounded-requirements.md`](waad-grounded-requirements.md) (DR-11–DR-64).

---

## Methodology

Files read in full before any claim was written:

- `app/index.html` — shell, script load order
- `app/js/tv-app.js` — keyboard router, tab bar, sidebar, empty state, theme/accent, recent files
- `app/js/tv-palette.js` — command palette: search groups, Commands group (theme/accent confirmed present), heading jump
- `app/js/tv-search.js` — cross-tab full-text search (⌘⇧F)
- `app/js/tv-native.js` — Tauri bridge, drag-drop handler, file-removed handler
- `app/js/tv-files.js` — drag-drop visual hint (.tv-drag-over), picker, save
- `app/js/tv-live.js` — live watch, status bar
- `app/js/tv-markdown.js` (first 80 lines) — no copy-code button found
- `app/css/tv-app.css` — full: drag-over hint confirmed; toast confirmed; copy-code button absent; no zoom/font-size controls
- `app/css/tv-tokens.css` — light/dark manual only; no `prefers-color-scheme` media query auto-switching
- `app/css/tv-tauri.css` — Tauri traffic-light overrides only
- `tauri-app/src-tauri/src/lib.rs` — no `tauri::Menu` / `menu::Menu` call anywhere; no `about`, `quit`, `find`, menu items
- `tauri-app/src-tauri/tauri.conf.json` — no `menu` key; no `tray` key

## Gap Table

| ID | Priority | Feature | Why Expected | Status | Suggested Implementation | Files |
|----|----------|---------|-------------|--------|--------------------------|-------|
| U-01 | **Must** | Native macOS menu bar | Every macOS app (Cocoa or Tauri) must register a menu. Without one: no File > Open, no ⌘Q, no ⌘M (minimise), no app About, no standard Edit menu (Copy, Select All, Undo), no Help. macOS drops the app name from the menu bar leaving a broken-looking bar. | **Missing** | Register a `tauri::menu::Menu` in `lib.rs run()` with: File (Open ⌘O, Close Tab ⌘W, separator, Quit ⌘Q), Edit (Copy ⌘C, Select All ⌘A), View (Toggle Sidebar ⌘B), Help (About, Keyboard Shortcuts). Wire menu items to `invoke` or Tauri events. | `tauri-app/src-tauri/src/lib.rs`, `tauri.conf.json` |
| U-02 | **Must** | Discoverable theme toggle (light / dark) | The persistent pill was removed (D-02). Theme/accent now lives exclusively inside ⌘K > Commands. A user who does not know ⌘K exists has no visible affordance to switch theme — the only sign is a faint "search files, headings, and commands" placeholder hint in the palette. macOS native viewers all expose a visible appearance toggle (toolbar icon, View menu, or OS auto-follow). | **Not discoverable** | Add a single low-visibility icon button to the titlebar (sun/moon SVG, 22×22, shown at ~40% opacity, tooltip "Toggle theme ⌘K → Theme"). Alternatively, add View > Appearance > Light / Dark to the native menu (U-01). Do not add chrome beyond a single icon or menu item. | `app/js/tv-app.js` `buildTitlebar()`, `app/css/tv-app.css`, or via native menu |
| U-03 | **Must** | ⌘F find-in-page (current document) | Every markdown viewer and browser provide ⌘F to locate text in the current file. The app wires ⌘F to open the sidebar search-box tooltip only (it renders `<span class="kbd">⌘F</span>` as an affordance label in the sidebar, but the key is not handled in the keyboard router — only ⌘⇧F is caught). Pressing ⌘F with a file open does nothing because the browser WebView's native find-bar is suppressed by the custom WebView. Users expect ⌘F = within-document search; ⌘⇧F = cross-file search. | **Missing** | Wire `k === 'f'` without shiftKey in the keyboard router to open a lightweight within-document find bar (highlight-and-scroll, not full TVSearch). Simplest: call `TVSearch.open()` scoped to the active tab only, or enable `window.find()` / browser native find if the Tauri WebView supports it. Distinguish the two modes in the UI with a scope label ("This file" vs "All tabs"). | `app/js/tv-app.js` keyboard router (line 698+) |
| U-04 | **Must** | Copy code-block button | Every modern markdown viewer (Bear 2, iA Writer, Typora, GitHub preview) shows a "Copy" button on hover over fenced code blocks. Developers using the app for AI output constantly copy code snippets. No copy affordance exists anywhere in the renderer. | **Missing** | In `tv-markdown.js` code-fence renderer, append `<button class="tv-copy-code" aria-label="Copy code" data-copy>` to each `<pre>` block. In `wireEvents()` or a separate init, delegate `click` on `[data-copy]` to `navigator.clipboard.writeText(pre.querySelector('code').textContent)` then flash a "Copied" toast. | `app/js/tv-markdown.js` (pre block render), `app/js/tv-app.js` `wireEvents()`, `app/css/tv-app.css` |
| U-05 | **Should** | Auto follow system appearance (light/dark) | macOS users expect apps to follow System Preferences > Appearance automatically. The token file has only `.tv--light` and `.tv--dark` classes toggled manually. The `color-scheme: light dark` on `:root` (tv-tokens.css line 10) covers native widgets but the app's own background colours are entirely class-driven and never auto-switch. A user who sets macOS to dark mode launches the app in light. | **Missing** | On init, call `window.matchMedia('(prefers-color-scheme: dark)')` and set initial theme accordingly if `localStorage.getItem('tv-theme')` is null. Register `mediaQuery.addEventListener('change', ...)` to update theme when the OS switches. Add "Auto (follow system)" as a third option in the Commands group alongside Light/Dark. | `app/js/tv-app.js` `init()`, `tv-palette.js` Commands rows |
| U-06 | **Should** | Keyboard shortcut help / cheat-sheet | Users cannot discover shortcuts they have not memorised. The app has 9+ shortcuts (⌘K, ⌘⇧F, ⌘B, ⌘O, ⌘E, ⌘S, ⌘W, ⌘1–9, Esc) with no in-app reference. Pressing ? in reading mode does nothing. Typora and iA Writer both provide a Help > Keyboard Shortcuts menu item or overlay. | **Missing** | Add a ? keyboard shortcut (reading mode, no modifier) that opens a minimal overlay listing all shortcuts — or add it as a "Keyboard Shortcuts" item in the Commands palette group, which renders a static list in the palette. A native menu Help > Keyboard Shortcuts would also satisfy this (covered by U-01). | `app/js/tv-app.js` keyboard router, `app/js/tv-palette.js` Commands group |
| U-07 | **Should** | Zoom / font size (⌘+ / ⌘−) | Reading comfort control is table stakes in any viewer. The content width is fixed at 720px (`--tv-content-max`) and font size at 16px with no in-app control. ⌘+ and ⌘− are intercepted by the keyboard router only partially (⌘1–9 is handled; ⌘= and ⌘- are not). Bear, iA Writer, and Obsidian all expose font-size or zoom controls. | **Missing** | Handle `k === '='` (⌘+) and `k === '-'` (⌘−) in the keyboard router to adjust a `--tv-content-font` CSS variable (stored in localStorage). Add the variable to `.tv .md` in tv-tokens.css with a default of 16px. Optionally expose "Increase text size" / "Decrease text size" in the Commands palette. | `app/js/tv-app.js` keyboard router, `app/css/tv-tokens.css` |
| U-08 | **Should** | Reveal in Finder / show file path | Users expect right-clicking a tab (or a menu item) to offer "Reveal in Finder" and "Copy file path". `tauri-plugin-opener` is already loaded (`lib.rs:284`) but never wired in the JS. The tab has `nativePath` available. The titlebar shows the filename but no path. | **Partial** | Wire `tauri-plugin-opener`'s `openPath` (or `revealItemInDir`) to a right-click context menu on `.tv-tab` elements. Add "Show in Finder" and "Copy path" as context menu items. At minimum, add a tooltip on `.tv-wintitle` that shows the full absolute path on hover. | `app/js/tv-app.js` `wireEvents()`, `app/js/tv-native.js` |
| U-09 | **Should** | Recent files in empty state | The empty-state dropzone shows "Drop .md files here — or — ⌘O to open files" with no list of recently opened files. All other macOS editors show recent files immediately in the open window or in a welcome panel. The recent-files list is already persisted in localStorage (`tv-recent-files`, max 10), but is never rendered to the user. | **Not discoverable** | In `buildEmpty()` / `buildViewer()` when no tabs are open, read `loadRecentPaths()` and render a short list of recent files below the dropzone with click-to-open behaviour (invoke `read_md_file` on click). This uses infrastructure that already exists. | `app/js/tv-app.js` `buildEmpty()`, `buildViewer()` |
| U-10 | **Should** | Tab context menu (right-click) | macOS users right-click tabs expecting: Close, Close Others, Close All, Reveal in Finder, Copy Path. None of these are present; right-click has no handler and falls through to the OS default (shows the WebView context menu with "Back", "Reload" etc. — inappropriate in a viewer). | **Missing** | Add a `contextmenu` handler to `.tv-tabbar` delegating on `[data-tab-id]`. Build a small positioned `<div>` menu with: Close Tab (⌘W), Close Others, Close All, separator, Reveal in Finder, Copy Path. Dismiss on click-outside or Escape. | `app/js/tv-app.js` `wireEvents()`, `app/css/tv-app.css` |
| U-11 | **Should** | Middle-click tab close | Standard browser and macOS tab UX: middle-click (auxiliary button) closes a tab. No handler exists for `button === 1` on tab elements. | **Missing** | Add a `mousedown` handler (not `click`, which doesn't fire for middle button reliably cross-platform) on `.tv-tab` that checks `e.button === 1` and calls `closeTab()`. | `app/js/tv-app.js` `wireEvents()` |
| U-12 | **Should** | Reload file from disk | When the file changes on disk and the user has made edits (dirty state), or when auto-watch is off, there is no way to manually reload the file from disk. Bear and Typora both have "Revert to saved" or "Reload". The app auto-watches via FSEvents, but if the user opened a file in another editor and made changes while tiny-viewer was open (without live watch), there is no reload affordance. | **Missing** | Add "Reload from disk" to the tab context menu (U-10) and to the Commands palette. The action calls `invoke('read_md_file', {path: tab.nativePath})` and overwrites `tab.source`, then renders. Confirm if tab is dirty. | `app/js/tv-native.js`, `app/js/tv-app.js`, `app/js/tv-palette.js` |
| U-13 | **Could** | Window / session restore on relaunch | The app restores recently-opened files via `tv-recent-files` in localStorage (implemented, E-02). However, it opens all recent files sequentially on every launch regardless of what was open in the last session, rather than restoring only the previous session's tabs and scroll positions. A user who had 3 files open, closed the app, and relaunched would get up to 10 recent files opened, not the 3 they had. | **Partial** | Persist a separate `tv-session` key in localStorage on `beforeunload` (array of `{nativePath, scrollTop}` for the current session's open tabs + activeId). On boot, restore only from `tv-session`; use `tv-recent-files` only for the empty-state recent list (U-09). | `app/js/tv-app.js` `init()`, `saveRecentPath()` |
| U-14 | **Could** | Tab drag-to-reorder | macOS users drag tabs to reorder them (standard in all browsers and Bear). No drag handler exists on tab elements. | **Missing** | Add HTML5 drag-and-drop (`draggable="true"`) to each `.tv-tab`. On `dragover` and `drop`, calculate the insertion index by comparing `e.clientX` to tab midpoints and splice `state.tabs` accordingly, then re-render. | `app/js/tv-app.js` `buildTabbar()`, `wireEvents()` |
| U-15 | **Could** | Export / print (⌘P) | Markdown viewers are often used to produce PDFs of documents (API docs, architecture notes). No print or export affordance exists. ⌘P is not handled. Tauri has `window.print()` / WebView print available. | **Missing** | Handle `k === 'p'` (meta) in the keyboard router to call `window.print()`. Add a print stylesheet in css/ that hides chrome (sidebar, tabbar, titlebar) and expands content to full width. Optionally add "Export as PDF" / "Print" to the Commands palette. | `app/js/tv-app.js` keyboard router, new `app/css/tv-print.css` |
| U-16 | **Could** | Outline / table-of-contents panel | Longer documents (architecture docs, API references) benefit from a quick heading outline. The command palette already parses headings per-document (tv-palette.js `_parseHeadings`). A dedicated outline panel or "Jump to heading" shortcut (e.g. ⌘⇧O) is not exposed as a standalone affordance separate from the full palette. | **Partial** | The palette heading jump already works. To make it discoverable without opening the full palette, add an "Outline" section to the sidebar below the file list (collapsible, hidden when the active doc has no headings). This re-uses `_parseHeadings` from tv-palette.js (expose it or duplicate it). | `app/js/tv-app.js` `buildSidebar()`, `app/js/tv-palette.js` |
| U-17 | **Could** | Sidebar keyboard navigation | Sidebar file rows are plain `<div>` elements with no `role`, no `tabindex`, no arrow-key navigation. Screen-reader and power-keyboard users cannot navigate the file list with arrow keys. The tab bar has ARIA roles (D-07 fix) but the sidebar does not. | **Partial** | Add `role="listbox"` to `.tv-side-scroll`, `role="option"` + `tabindex="0"` (active file) / `tabindex="-1"` (others) to each `.tv-tree-row.file`. Handle `ArrowUp` / `ArrowDown` / `Enter` / `Space` within the sidebar. | `app/js/tv-app.js` `buildSidebar()`, `app/css/tv-app.css` |
| U-18 | **Could** | File association / Open With | Users expect to right-click a `.md` file in Finder and see "tiny-viewer" in "Open With". No `UTTypeConformsTo` / `CFBundleDocumentTypes` entry exists in the Tauri bundle config. Without it, the app never appears in Finder's Open With menu and cannot be set as the default markdown viewer. | **Missing** | Add a `fileAssociations` entry in `tauri.conf.json` under `bundle` for `text/markdown` (`.md`, `.markdown`) and optionally `text/plain` (`.txt`). Tauri v2 supports `bundle.fileAssociations`. Wire the `tauri://file-drop` event (already present in TVNative) to handle files opened via Finder. | `tauri-app/src-tauri/tauri.conf.json`, `app/js/tv-native.js` |

## Notes on Items Verified as Present (Not Gaps)

The following were listed as candidates to check but are confirmed implemented:

- **Theme/accent switching** — present via ⌘K > Commands group (tv-palette.js lines 88–97). Gap is discoverability only (U-02).
- **Cross-tab search (⌘⇧F)** — fully implemented in tv-search.js. Distinct keyboard binding confirmed (tv-app.js line 728).
- **Drag-drop visual hint** — `.tv-drag-over` CSS exists and is wired in tv-files.js (lines 38–44, 108–111). Present.
- **File watch / live update (⌘ live indicator)** — implemented via FSEvents in tv-live.js + tv-native.js.
- **Scroll position preservation** — E-04 resolved; implemented in activateTab().
- **Toast error notifications** — `showToast()` present in tv-native.js (lines 150–160); CSS confirmed in tv-app.css (lines 774–791).
- **Reduced-motion respect** — `@media (prefers-reduced-motion: reduce)` block at tv-app.css lines 809–845.
- **ARIA on tab bar** — D-07 resolved; `role="tablist"`, `role="tab"`, `aria-selected`, `aria-label` on close buttons confirmed in tv-app.js lines 133–171.
- **Command palette ARIA** — `role="listbox"`, `role="option"`, `aria-label` on input confirmed in tv-palette.js.
- **Empty-state guidance** — dropzone with drop-target hint + ⌘O callout exists in `buildEmpty()`. Gap is absence of recent-files list (U-09).
- **File-removed handler** — E-08 confirmed fully resolved: `handleFileRemoved()` in tv-native.js (lines 163–186) and `listen('file-removed', ...)` registered in `init()` (line 296).
