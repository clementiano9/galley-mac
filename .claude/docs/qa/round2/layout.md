| L-01 | **High** | DR-02 / Content readability | `.md pre { overflow: hidden }` clips wide code blocks instead of allowing horizontal scroll. Any line longer than the content column (720 px max-width minus 80 px padding = ~640 px, or less with a sidebar) is silently truncated. This is the calibration-example class of bug: `overflow: hidden` on a block-level code container is a clip, not a scroll. The `.md pre code` child has `display: block` and `white-space` is not overridden, so long lines paint beyond the pre boundary and vanish. | `tv-app.css:314` | Change `.md pre { overflow: hidden }` to `overflow-x: auto`. | L-02 | **High** | DR-02 / Wide tables | `.tv-scroll { overflow-x: hidden }` and `.md .tbl-wrap { overflow: hidden }` together make wide tables impossible to scroll horizontally. A table with 8+ columns or a column containing a long URL will be clipped at the scroll container edge with no affordance that content exists beyond. The `tbl-wrap` `overflow: hidden` is intentional for `border-radius` clipping, but `overflow-x: hidden` on `.tv-scroll` is the outer cage that prevents any recovery. | `tv-app.css:198` (`.tv-scroll overflow-x:hidden`); `tv-app.css:332` (`.tbl-wrap overflow:hidden`) | Change `.tv-scroll` to `overflow-x: hidden` → `overflow: auto` (or keep `overflow-y: auto; overflow-x: hidden` at `.tv-scroll` level but change `.tbl-wrap` to `overflow-x: auto` so the table can scroll within its wrapper). | L-03 | **High** | DR-07 / DR-09 / Many-tab affordance | The `.tv-newtab` button uses `mask-image: none` as a "counter-mask" to escape the parent `.tv-tabbar` gradient fade (`linear-gradient(…, transparent 100%)`). The button sits 34 px from the right edge, inside the last 48 px of the fade zone, so it is rendered at near-zero opacity. This lets the newtab button remain fully opaque and clickable. Alternatively, move the newtab button outside the scrolling `.tv-tabbar` flex container and give it its own background — it should be a sibling to the scroll strip, not a child. |

## Notes on Out-of-Scope Items

The following were checked and found not to be issues:

- **Palette on narrow windows**: `width: 560px; max-width: calc(100% - 80px)` correctly adapts at the 720 px minimum window width.
- **Wintitle tab overlap**: The 84 px left padding in Tauri mode clears the 78 px native traffic-light cluster (12 px buttons × 3 + 6 px gaps + margins). No overlap.
- **Edit-mode textarea vertical alignment**: Both the textarea and backdrop share `padding-top: var(--tv-s4)` and are co-located in the same `position: relative` wrapper. First-line alignment is correct.
- **Palette `.tv-pal-list` overflow**: Fixed in round 1 (D-04) — confirmed `overflow-y: auto; overflow-x: hidden` at `tv-app.css:573`.
- **Sidebar scroll**: Fixed in round 1 (E-09) — confirmed `overflow-y: auto` at `tv-app.css:153`.
- **Dark theme contrast**: All accent colors on dark backgrounds pass WCAG-AA. Muted text fails both themes (covered by L-06).
- **Edit-wrap height tracking**: `updateBackdrop()` is called on every `onInput` event, keeping the backdrop in sync with textarea content during editing. The initial brief misalignment on load is subsumed by L-08 (bottom padding mismatch).
