## New work role and requirement (proposed)

**WR4 Agent Operator** (a facet of Role 1, AI Content Reviewer). Steers one or more coding agents all day. Reads and edits the markdown that governs the agents (instruction files, rules, skills, specs, saved chats) and reviews the markdown the agents write. Opens a project root and expects to see those files without hunting through hidden folders, and without a tree full of unrelated tool folders.
- Pain points: URD-05, URD-06, URD-10. New: URD-11.
- Key WANs: 082 to 099.

**URD-11 Agent instruction files** *(All work roles using agents; primary: WR4)*. Coding agents keep their instructions, rules, skills, plans and history as markdown, either in the project root (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`) or in tool-named dot-folders (`.claude`, `.cursor`, `.github`, `.kiro`, `.codex`, and others). These files are the product's own audience's working documents. A viewer for this audience shows them by default and does not drown them in unrelated hidden folders. *Supporting WANs: 082 to 099.*

## A. Table width (UXF-01)

| WAN | Source | What it says | Used for |
|---|---|---|---|
| 075 | [github-markdown-css](https://raw.githubusercontent.com/sindresorhus/github-markdown-css/main/github-markdown.css) (the stylesheet behind GitHub's rendered markdown) | `table { display: block; width: max-content; max-width: 100%; overflow: auto; }` | GitHub never lets a table exceed the text column: it fills at most 100% and scrolls inside. A cap, but no notion of need, and no bleed |
| 076 | [Notion Help: columns, headings and dividers](https://www.notion.com/help/columns-headings-and-dividers) and [tables](https://www.notion.com/help/tables) | Simple tables have `Fit to page width`; columns are resized by dragging; `Wrap text` is a per-table setting | Notion makes width a per-table user choice; we have no per-table control and want a good default instead |
| 077 | [Baymard: Readability, the optimal line length](https://baymard.com/research-articles/line-length-readability) | Optimal line length for body text is 50 to 75 characters | A prose column wider than about 45 to 75 characters is past the readable measure: the case for a prose threshold and a ceiling |
| 078 | [UXPin: optimal line length](https://www.uxpin.com/studio/blog/optimal-line-length-for-readability/) (third party) | 50 to 75 characters, 66 the usual target; Bringhurst 45 to 75; novices 34 to 60 | Same; supports a lower measure for dense cells |
| 079 | [MDN: table-layout](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/table-layout) | With `width: auto`, the automatic table layout algorithm applies | The browser already derives each table's min-content and max-content widths: we read them (`M`, `W`) instead of guessing |
| 080 | [Medium: adding tables to stories](https://fletchjeff.medium.com/adding-tables-to-medium-stories-47a663e98966) (third party) | Medium has no native tables; authors paste images of tables | The far end of the range: no table at all. No width lesson |
| 081 | [iA Writer: tables and charts](https://ia.net/presenter/support/story/tables-and-charts) | Markdown tables are "easier to read than HTML, but still a weak spot" | No documented width behaviour found |

**Reading of the evidence.** The two products that support tables settle the question differently: GitHub caps at the column; Notion gives the author a switch. Neither sizes by what the table needs. Our own measurement (step 8, E5 and iteration 2) shows the cost of sizing by what a table wants: a prose table stretched to 1,122 px. The chosen rule sizes by need and content kind, with a bounded bleed for prose (UXF-01).

## C. Motion (UXF-08)

| WAN | Source | What it says | Used for |
|---|---|---|---|
| 100 | [Apple HIG: Motion](https://developer.apple.com/design/human-interface-guidelines/motion) | "Add motion purposefully, supporting the experience without overshadowing it." "Make motion optional." "Aim for brevity and precision in feedback animations." "In apps, generally avoid adding motion to UI interactions that occur frequently." "Let people cancel motion." "Consider using fades when you need to relocate an object." | Principles 1, 2, 7; the "static" decisions for tab switch and close |
| 101 | [WWDC23: Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/) | Linear animations feel non-physical for movement; springs preserve velocity; bounce 0 gives a smooth settle with no oscillation | No bounce, no linear for movement: `--tv-ease-move` is a critically damped curve |
| 102 | [WebKit blog: Responsive Design for Motion](https://webkit.org/blog/7551/responsive-design-for-motion/) | macOS added Reduce Motion in 2016; WebKit's `prefers-reduced-motion` media feature reflects it | In WKWebView the macOS setting is the media query: no extra setting needed |
| 103 | [NN/g: animation duration and motion characteristics](https://www.nngroup.com/articles/animation-duration/) | Most UI animations belong in 100 to 500 ms; about 100 ms feels immediate; 500 ms starts to drag; 400 ms is only for big movements across large screens | Token durations 100, 160, 220 |
| 104 | [performance.dev: how Linear is so fast](https://performance.dev/how-is-linear-so-fast-a-technical-breakdown) (third-party analysis of Linear's stylesheet) | Linear's speed variables: highlight fade-in 0, fade-out .15 s, quick .1 s, regular .25 s, slow .35 s; hover highlights, popovers and the agent panel appear instantly and fade out over 150 ms; motion "doing spatial work" rather than decoration | Enter fast, leave instant or faster; palette and menus close instantly |
| 105 | [Aerotwist: FLIP your animations](https://aerotwist.com/blog/flip-your-animations/) and [CSS-Tricks: FLIP](https://css-tricks.com/animating-layouts-with-the-flip-technique/) | First, Last, Invert, Play: measure the start and end, apply the layout change at once, then animate `transform` and `opacity` from the inverted position | The sidebar technique: one reflow, then transforms only |
| 106 | [Things features page](https://culturedcode.com/things/features/) | Its small animations are "achieved with our own, custom built animation toolkit" | Reference only: a polished Mac app treats motion as a system, not per-component CSS |
| 107 | [Material 3: easing and duration](https://m3.material.io/styles/motion/easing-and-duration) | Defines easing and duration token sets; the Standard set is for small, quick, utility transitions | Precedent for tokens rather than literals |

**Reading of the evidence.** The shared pattern in the references is short enters (100 to 250 ms), faster or instant exits, motion that shows where a thing came from, none on frequent actions, and a token set. Apple's own guidance adds the cancel-ability and Reduce Motion rules. FLIP is the technique that reconciles "animate the sidebar" with "the DOM is replaced on every render".
