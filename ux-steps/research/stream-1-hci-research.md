# Stream 1: UX/HCI Academic Research
*WANs 001–015 | Focus: cognitive load, context switching, editor UX*

---

[WAN-001] [Source: https://super-productivity.com/blog/context-switching-costs-for-developers/] [Work Role: Knowledge Worker / Developer]
Gloria Mark (UC Irvine) found that knowledge workers switch tasks every 3 minutes on average, and after a significant interruption it takes an average of 23 minutes and 15 seconds to fully regain focus on the original task.

[WAN-002] [Source: https://super-productivity.com/blog/context-switching-costs-for-developers/] [Work Role: Developer]
Sophie Leroy (University of Washington) documents "attention residue" — after switching files or tasks, part of working memory remains anchored to the prior task, degrading performance on the new one; the more engaging the interrupted task, the stronger the residue effect.

[WAN-003] [Source: https://medium.com/@codewithmunyao/the-hidden-cost-of-context-switching-why-your-most-productive-hours-are-disappearing-43c5b501de19] [Work Role: Senior Developer]
A two-week experiment tracking 50 developers found they averaged 47 context switches per day, yielding only 2.3 hours of genuine deep-focus work out of an 8-hour day; one senior developer spent 27% of his day purely waiting for or switching between tools.

[WAN-004] [Source: https://blog.continue.dev/the-hidden-cost-of-tool-switching/] [Work Role: Developer]
Research consistently shows that switching between an IDE and an external tool such as a chat assistant produces at minimum four discrete context switches per interaction; an interrupted task can take twice as long and contain twice as many errors as an uninterrupted one.

[WAN-005] [Source: https://zuunote.com/blog/markdown-headings-wysiwyg-ux-studies/] [Work Role: Technical Writer / Developer]
A UX case study of markdown heading rendering found that with split-pane editors users must continuously shift visual attention between the left editing pane and the right preview pane; this divided-attention demand was described as "exhausting" and led to calls for inline WYSIWYG feedback as a direct replacement for the two-pane model.

[WAN-006] [Source: https://www.reddit.com/r/ObsidianMD/comments/1fz7xbi/what_is_the_purpose_of_separate_markdown/] [Work Role: Technical Writer / Visual Designer]
Obsidian users report that inconsistent rendering between "Reading" and "Live Preview" modes — caused by the app using separate rendering engines for each — forces repeated tinkering to align visual appearance, diverting attention away from content creation and toward tool configuration.

[WAN-007] [Source: https://www.newyorker.com/magazine/2021/12/20/can-distraction-free-devices-change-the-way-we-write] [Work Role: Writer / Designer / Programmer]
iA Writer's focus mode, which highlights only the active line and fades completed text to gray, accumulated over half a million active users predominantly among designers, programmers, and journalists — segments whose professional cognitive demands make UI chrome reduction particularly valuable.

[WAN-008] [Source: https://legendfiction.substack.com/p/i-tested-23-writing-toolsyeah-almost] [Work Role: Writer / Developer]
A practitioner who tested 22 writing tools identified "poor or overly busy design" and "writing interfaces that don't feel good" as the primary blockers to sustained writing; tools with online-only access were specifically flagged as a distraction vector because opening a browser triggers habitual tab-switching behavior.

[WAN-009] [Source: https://pmc.ncbi.nlm.nih.gov/articles/PMC12611650/] [Work Role: Researcher / Writer]
Cognitive Load Theory distinguishes extraneous cognitive load — generated by suboptimal interface conditions that consume mental resources without contributing to the writing task, such as unclear UI or distracting chrome — as directly harmful to writing output quality; reducing extraneous load frees working memory for germane (skill-building) processing.

[WAN-010] [Source: https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2025.1671214/full] [Work Role: Knowledge Worker]
A 2025 meta-analysis found that distractions in digital reading environments — including hyperlinks and multimodal UI elements — significantly impair reading comprehension by increasing attentional interference load; the effect is present even when the distractor is peripherally visible rather than actively clicked.

[WAN-011] [Source: https://mjambon.github.io/vim-vs-emacs/] [Work Role: Researcher / Academic Writer]
A 40-participant controlled usability study (ISO 9241-10 questionnaire) comparing text editors found measurable differences in error rates, text volume produced, and formatting accuracy across editors — demonstrating that editor choice has a direct, quantifiable effect on writing productivity independent of user skill level.

[WAN-012] [Source: https://froala.com/blog/general/wysiwyg-vs-markdown-developer-docs/] [Work Role: Developer / Technical Writer]
Desktop-based WYSIWYG editors demonstrate more platform compatibility issues than Markdown-native editors; developers consistently prefer Git-friendly plain text for its clean diffs and review toolchain integration, while non-technical collaborators require the visual clarity of WYSIWYG — creating workflow friction when teams share a single editor paradigm.

[WAN-013] [Source: https://medium.com/yandex/markdown-editor-wysiwyg-and-markup-editor-based-on-gravity-ui-43e97183ac8d] [Work Role: Developer / Content Author]
Yandex engineers building a dual-mode WYSIWYG/Markdown editor observed that users frequently needed to reformat and rewrite text when moving between single-paradigm tools, identifying forced tool-switching as a chronic productivity tax; combining both modes in a single editor with a shared .md storage format eliminated this reformatting overhead.

[WAN-014] [Source: https://github.blog/developer-skills/github/include-diagrams-markdown-files-mermaid/] [Work Role: Developer / Technical Writer]
GitHub's rollout of native Mermaid diagram rendering in Markdown files addressed a longstanding documentation gap: previously, developers had to leave the Markdown editing context entirely to create diagrams in external tools, then embed static images — a multi-step workflow that broke document-as-code continuity and increased diagram staleness.

[WAN-015] [Source: https://jakobnielsenphd.substack.com/p/ui-annoyances] [Work Role: All Desktop Users]
Jakob Nielsen identifies UI chrome — interface control widgets surrounding content — as a direct source of cognitive load; designs that strip chrome too aggressively impair navigation (e.g., anorexic scrollbars increase mis-click rate), while excessive chrome raises extraneous load, indicating that the optimal markdown editor UI sits at a carefully tuned minimum — not zero — chrome threshold.
