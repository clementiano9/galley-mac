# Stream 4: Industry Reports & Practitioner Articles
*WANs 051–062 | Focus: developer productivity, AI workflow, knowledge management*

---

[WAN-051] [Source: https://survey.stackoverflow.co/2025/technology] [Work Role: Software Developer]
In the 2025 Stack Overflow Developer Survey (30,065 respondents), Markdown files rank as the third most-used async/knowledge tool among professional developers at 25.6% usage, with a 59.5% "admired" (want to keep using) rate — higher than Confluence — indicating strong loyalty among the subset who adopt it.

[WAN-052] [Source: https://survey.stackoverflow.co/2025/technology] [Work Role: Software Developer]
Obsidian appears in the Stack Overflow 2025 survey with a 9.9% current-usage rate and a 49.1% admired rate among professional developers, placing it ahead of Notion (9.5% / 54.3%) in raw usage, suggesting meaningful grassroots adoption of local file-based PKM within the developer community despite no enterprise mandate.

[WAN-053] [Source: https://stackoverflow.co/internal/resources/your-developers-deserve-better-insights-from-the-2024-developer-survey/] [Work Role: Engineering Manager / Developer Experience Lead]
Stack Overflow's 2024 Developer Survey analysis finds that developers are measurably more productive when they can self-serve answers without interrupting colleagues, and organizations that centralize knowledge on a searchable platform report faster time-to-value and reduced context-switching overhead.

[WAN-054] [Source: https://www.xda-developers.com/sick-of-proprietary-notetaking-tools-plain-text-is-better/] [Work Role: Software Developer / Technical Writer]
Developer-focused practitioners report that plain-text and Markdown note systems offer meaningfully faster search than database-backed apps like Notion, because the OS can index files directly without app-level rendering latency — an advantage that compounds as note count grows into the thousands.

[WAN-055] [Source: https://www.xda-developers.com/sick-of-proprietary-notetaking-tools-plain-text-is-better/] [Work Role: Software Developer]
A recurring motivation for file-based note systems is portability across tools: developers explicitly choose Markdown because switching apps requires zero migration effort, treating vendor independence as a first-class feature rather than an afterthought.

[WAN-056] [Source: https://news.ycombinator.com/item?id=38732437] [Work Role: Software Developer]
Hacker News practitioners report using Obsidian and VS Code simultaneously on the same Markdown vault — opening files in whichever editor fits the current task — because Obsidian's file-system backend detects external changes near-instantly, enabling a fluid multi-tool editing pattern without sync friction.

[WAN-057] [Source: https://peer.asee.org/tips-for-creating-a-functional-personal-knowledge-management-system-in-academia.pdf] [Work Role: Knowledge Worker / Researcher]
Practitioners building personal knowledge management systems cite non-proprietary file formats as their top selection criterion — above cost and cross-platform availability — specifically to ensure notes remain readable without any particular application decades into the future.

[WAN-058] [Source: https://idlen.io/blog/15-ai-tools-improve-developer-workflow/] [Work Role: Software Developer]
A 2024-2025 practitioner evaluation of AI developer tools found that documentation generators like Mintlify still require "significant human editing for quality documentation" — the tool accelerates a starting draft but cannot replace thoughtful technical writing — framing AI output as a first-draft accelerator, not a finished artifact.

[WAN-059] [Source: https://techreviewer.co/blog/how-ai-reshaping-development-workflows-in-2025] [Work Role: Software Developer / Engineering Lead]
A 2025 developer workflow study found the majority of teams verify AI-generated code in 100% of cases, treating AI output as a mandatory-review draft rather than trusted output; the most common errors caught are behavioral and contextual (logic errors, security risks, poor codebase fit) rather than syntax mistakes that linters catch.

[WAN-060] [Source: https://www.morphik.ai/blog/ai-tools-for-technical-docs] [Work Role: Technical Writer / Documentation Engineer]
Benchmark data shows engineering teams spend 5-8 hours weekly on manual document review and error correction; AI-powered documentation tools reduce API doc creation time from 8 hours to 2.5 hours while raising completeness from 76% to 94%, but the time savings are concentrated in generation and formatting — human review of accuracy remains a required step.

[WAN-061] [Source: https://www.nngroup.com/topic/writing-web/] [Work Role: UX Writer / Content Designer]
Nielsen Norman Group's guidance on AI-generated web content specifies that generative AI outputs must be edited to be concise, scannable, follow the inverted pyramid, and use plain language — implying a mandatory human editing pass is embedded in any responsible AI writing workflow, not optional post-production.

[WAN-062] [Source: https://dev.to/sc0v0ne/my-super-powers-as-a-software-developer-2024-1h17] [Work Role: Software Developer]
A developer writing about their 2024 toolchain describes Obsidian synced to a personal GitHub repository as their core daily knowledge system, valuing the combination of Markdown simplicity, version-controlled history, and the ability to return to and iterate on previous notes — reflecting a git-native documentation mindset extending beyond code into personal knowledge.
